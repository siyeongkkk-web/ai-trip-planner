# AI Trip Planner 公开版评测说明

## 评测要回答什么

旅行规划 Agent 不只需要“说得像对的”，还要在完整产品流程中完成正确动作。因此每道 Development 题分别检查：

1. **理解：** 是否识别用户的目标、对象、限制和修改权限；
2. **执行：** 是否把要求带入工具参数，并正确使用工具返回的信息；
3. **结果：** 最终方案、回复和行程状态是否符合用户要求；
4. **安全边界：** 是否在用户确认前修改行程，或在失败时污染原状态。

## 题目从哪里来

题目主要来自：

- 对产品的反复实际使用，包括自然语言误解、多要求遗漏、地点歧义、外部事实不足、工具失败和行程状态不一致；
- 产品必须具备的能力，包括单份综合行程、多轮调整、用户确认、失败恢复和事实诚实。

这些问题被归纳为 7 类能力，并形成 48 道 Development 题。48 道题共拆成 187 个检查点。

## 如何判断

- 地点身份、确认状态、版本、写入和回滚使用确定性检查；
- 工具参数、调用过程和返回信息的使用情况通过运行过程记录检查；
- 回复是否清楚、取舍是否有帮助由人工评分；
- LLM Judge 仅作为待校准的辅助方法，不参与当前正式结论。

硬性安全问题不能被较好的文字表达抵消。

## Development 与正式评测题

- **Development：** 48 道，可查看题目和运行结果，用于定位问题、修改产品和重复回归；
- **正式评测题：** 28 道，独立保存，当前尚未运行。

正式评测题、参考答案和逐题检查材料不进入公开仓库。公开仓库只披露数量、覆盖范围、方法和当前进度。

## 当前进度与边界

当前已完成 Development 题、检查点、运行工具和部分人工评分材料的准备，正在继续校准人工评分规则。尚未运行正式评测题，因此：

- 没有正式通过率；
- 不能声称产品已经通过评测；
- 不能用离线固定事实结果代表真实高德服务或页面体验；
- 不能用 AI 或单人标注结果代表真实用户长期体验。
