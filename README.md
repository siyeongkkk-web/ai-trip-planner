# AI Trip Planner｜智能旅行规划 Agent

> **产品状态：仍在迭代优化中，产品功能与界面设计均在持续完善，当前版本并非最终版本。**

把用户分散在攻略、地图、酒店和交通平台的信息，整理成一份**能执行、能核对、还能继续修改的旅行行程**。

## 在线查看产品

**[打开 AI Trip Planner](https://ai-trip-planner-alpha-ten.vercel.app)**

用户无需登录即可打开，查看当前产品形态、信息填写入口和主要页面流程。公开网站没有上传个人 DeepSeek 和高德 API Key，因此目前不能调用真实行程生成、地点核验和路线服务；完整功能需按下方说明在本地配置。

## 我想解决的问题

用户通常已经在小红书等平台收藏了想去的地点，但真正排行程时仍要反复切换攻略、地图、酒店和交通平台：

- 攻略里的地点需要重新整理和核对；
- 大模型可能编造地点、距离或营业时间；
- 一句话包含多个要求时，模型可能只完成一部分；
- 修改行程时，容易误删其他活动，或者在失败后仍提示成功。

因此，这个产品不只是“生成一段旅行攻略”，而是把旅行信息整理、地点核验、路线安排和后续修改串成一条完整流程。

## 产品怎么使用

### 方式一：直接填写旅行信息

填写日期、往返交通、酒店、想去地点和旅行偏好，生成一份综合行程。

### 方式二：从帖子或截图开始

粘贴帖子正文或上传截图，产品先提取原文中出现的地点，保留对应证据，用户勾选后再通过高德地图核验，最后进入行程规划。

### 行程生成后：继续让 Agent 修改

用户可以提出新增、删除、替换、延长或移动活动等要求。Agent 先给出调整方案，只有用户确认后，产品才会真正修改行程。

```text
旅行信息 / 帖子 / 截图
          ↓
提取并核对地点
          ↓
生成一份综合行程
          ↓
用户提出修改要求
          ↓
Agent 给出方案 → 用户确认 → 写入行程
```

## 三个关键产品决策

### 1. 不让大模型同时负责所有事情

- **LLM**：理解用户要求，判断需要调用什么工具；
- **高德地图**：提供地点身份、坐标、路线和可查询的外部信息；
- **确定性代码**：处理时间安排、用户确认、版本检查、行程写入和失败回滚。

这样可以减少地点和路线编造，也避免模型在没有确认时直接改动用户行程。

### 2. Agent 先提方案，用户确认后再修改

每次调整分成两步：

1. Agent 根据当前行程提出具体修改方案；
2. 用户确认后，代码检查行程版本和修改结果，再决定是否写入。

如果请求过期、目标活动不存在、工具失败或修改结果不符合要求，原行程保持不变，页面不能假装修改成功。

### 3. 把“听懂”与“做对”分开检查

评测题主要来自两部分：自己反复使用产品发现的问题，以及产品必须具备的能力。目前归纳为 7 类问题：

- 语义理解；
- 多项要求处理；
- 规划合理性；
- 地点身份；
- 外部事实是否诚实；
- 工具失败后的处理；
- 多轮对话中的上下文保持。

现阶段已建立：

- 48 道 Development 题，用于开发和回归；
- 187 个检查点，分别检查是否理解正确、执行正确、结果正确，以及是否守住安全边界；
- 28 道独立正式评测题，**尚未运行**；
- 人工评分规则仍在校准，因此目前没有正式产品得分。

详细方法见[公开版评测说明](docs/PUBLIC_EVALUATION_OVERVIEW.md)。

## 当前已经实现

- 直接填写旅行信息并生成综合行程；
- 从正文或截图提取地点，用户选择后再进行地图核验；
- 往返交通与酒店确认；
- 地点、路线和时间轴整理；
- Agent 新增、删除、替换、延长和移动活动；
- 修改前确认、行程版本检查和失败回滚；
- 行程完整性检查、费用估算和导出。

## 技术组成

- Next.js 16、React 19、TypeScript、Tailwind CSS；
- DeepSeek API：地点提取、活动初稿和自然语言理解；
- 高德地图 Web 服务：地点核验、路线、周边搜索和天气；
- macOS Vision：本地中文截图 OCR；
- localStorage：在浏览器本地保存行程草稿和历史记录。

## 在本地运行完整版本

```bash
npm install
cp .env.example .env.local
npm run dev
```

在 `.env.local` 中配置：

```bash
DEEPSEEK_API_KEY=your-deepseek-api-key
AMAP_KEY=your-amap-web-service-key
```

然后打开 <http://localhost:3000>。

截图 OCR 使用 macOS Vision，因此仅能在安装 Swift 的 macOS 本地环境运行。其他页面不受这一限制。
