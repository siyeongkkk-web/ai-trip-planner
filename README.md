# AI Trip Planner｜智能旅行规划 Agent

根据用户的日期、往返交通、酒店、想去地点和旅行偏好，生成一份可执行的多日行程；行程生成后，用户还可以通过旅行规划 Agent 继续新增、删除、替换或移动活动。

> **项目状态：持续迭代中。** 当前公开版本用于展示产品流程、Agent 设计和评测方法，UI 仍在优化，不代表最终视觉方案。

## 在线体验

[在线体验 AI Trip Planner](https://ai-trip-planner-alpha-ten.vercel.app)

公开展示版可以查看主要页面与交互流程。DeepSeek、高德地图和 macOS Vision OCR 需要开发者自行配置密钥或本地环境；仓库和线上部署均不包含个人 API 密钥。

## 产品解决什么问题

旅行规划往往需要在攻略、地图、酒店和交通平台之间反复整理信息。本项目提供两种开始方式：

1. 直接填写日期、往返交通、酒店、地点和偏好，生成一份综合行程；
2. 粘贴旅行帖子正文或上传截图，先提取并核对地点，再进入规划。

产品目标不是让大模型代替地图和预订平台，而是帮助用户把分散的信息整理成一份能执行、能核对、还能继续调整的行程。

## 关键设计

### 1. 生成一份可核对的初始行程

- DeepSeek 根据用户输入生成活动初稿；
- 高德地图补充地点身份、坐标和真实路线；
- 确定性代码根据交通耗时、活动时长和返程时间重建时间轴；
- 行程检查会提示地点遗漏、地图身份缺失、时间重叠和餐饮缺口。

### 2. 从帖子或截图导入地点

- 模型只能提取原文中明确出现的地点，并保留对应证据片段；
- 用户可以编辑、选择或删除候选地点；
- 选中的地点必须通过高德地图核验后才能保存；
- 小红书链接只作来源记录，服务端不绕过平台限制抓取正文。

### 3. 设计受限的旅行规划 Agent

- Agent 读取当前行程和用户要求，按需调用地点、路线、营业时间和插入位置等工具；
- Agent 先提出调整方案，用户确认后才会修改行程；
- 版本冲突、未授权活动和写入失败由代码检查；失败时保留原行程；
- 天气和区域交通只生成待确认风险，不会自动改动计划。

## Agent 评测进度

评测题主要来自两部分：自己反复使用产品发现的问题，以及产品必须具备的能力。

- 7 类能力：语义理解、多要求处理、规划合理性、地点身份、事实诚实、失败恢复、多轮上下文；
- 48 道 Development 题，用于反复调试和回归；
- 187 个检查点，分别检查理解、执行、结果和安全边界；
- 28 道独立正式评测题已准备，但尚未运行；
- 当前正在完成人工标注和评分规则校准，尚无正式产品得分。

更多说明见[公开版评测说明](docs/PUBLIC_EVALUATION_OVERVIEW.md)。

## 技术栈

- Next.js 16、React 19、TypeScript、Tailwind CSS
- DeepSeek API：地点抽取、活动初稿和自然语言理解
- 高德地图 Web 服务：地点核验、路线、周边搜索和天气
- macOS Vision：本地中文截图 OCR
- 浏览器 localStorage：本地保存行程草稿与历史记录

## 本地运行

```bash
npm install
cp .env.example .env.local
npm run dev
```

在 `.env.local` 中配置：

```bash
DEEPSEEK_API_KEY=your-deepseek-api-key
AMAP_KEY=your-amap-web-service-key
```

打开 <http://localhost:3000>。

截图 OCR 依赖 macOS Vision，仅能在安装 Swift 的 macOS 本地环境运行。没有配置 DeepSeek 或高德密钥时，相关在线能力不会工作。
